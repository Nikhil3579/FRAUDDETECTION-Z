
evaluate.py

Main metrics
------------
1. PR-AUC
   Precision-Recall Area Under Curve.

2. Recall @ FPR
   Measures how much fraud we can detect while keeping the false
   positive rate below a business-defined limit.

3. Confusion Matrix
   Shows:
       TN = True Negative
       FP = False Positive
       FN = False Negative
       TP = True Positive

4. Precision
   Of all transactions predicted as fraud, how many were actually fraud?

5. Recall
   Of all actual fraud transactions, how many did the model detect?

6. F1-score
   Harmonic mean of precision and recall.

Why PR-AUC?
------------
Fraud detection is a classification problem where the positive class
(fraud) is usually much smaller than the negative class.

Accuracy alone can be misleading.

For example:
    If 95% of transactions are legitimate, a model that predicts
    every transaction as legitimate can achieve 95% accuracy while
    detecting ZERO fraud.

PR-AUC focuses on the precision and recall of the positive class,
making it more informative for fraud detection.

Why not use only ROC-AUC?
-------------------------
ROC-AUC is useful, but with strong class imbalance it can sometimes
look better than the actual fraud-detection performance because the
False Positive Rate is influenced by the large number of legitimate
transactions.

Therefore, this project uses PR-AUC as the PRIMARY ranking metric.

Why Recall @ FPR?
-----------------
A fraud detection system must balance fraud detection against
false alarms.

Example:

    "If the company can tolerate at most 5% false positives,
     how much fraud can the model detect?"

This is represented by:

    Recall @ FPR <= 0.05

The target FPR is configured in config.py.

Important
---------
Metrics such as PR-AUC and Recall@FPR use predicted probabilities.

The classification metrics (precision, recall and F1) use a
decision threshold.

Default threshold:
    0.50

The final project can later optimize this threshold using the
validation set based on business costs.

Run
---
This module is normally imported by other training scripts:

    from .evaluate import full_report, print_report

---------------------------
XGBoost performance depends heavily on parameters such as:

    - learning_rate
    - max_depth
    - n_estimators
    - subsample
    - colsample_bytree
    - min_child_weight
    - gamma
    - reg_alpha
    - reg_lambda

Manually testing combinations is slow and difficult to reproduce.

Optuna automatically searches the parameter space.

Optimization objective
----------------------
The project uses:

    PR-AUC / Average Precision

as the primary optimization metric because this is a fraud detection
problem and the positive class is the important class.

 recision and recall can conflict.

For example:

Precision = 95%
Recall = 60%

Excellent precision, but the model is missing many fraud cases.

Another model might have:

Precision = 75%
Recall = 90%

F1 gives a balance between them.

Formula:

F1 = 2 × Precision × Recall
     ─────────────────────────
       Precision + Recall
